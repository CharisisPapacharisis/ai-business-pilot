# AI Business Pilot

AI Business Pilot is a local-first prototype for evidence-based business
analysis across structured data and operational work items. It uses a local
language model to decide which information sources a question requires, calls
those sources through the Model Context Protocol (MCP), and produces a report
grounded in retrieved evidence.

All included business data is fictional, and monetary values are treated as
USD.

## What it does

The current workflow can:

- analyze customers, products, orders, revenue, and gross profit in DuckDB;
- retrieve proposals, initiatives, and current work-item status from Linear;
- combine proposal context with measured business performance;
- route questions to DuckDB, Linear, or both systems;
- retain conversation context within a checkpointed thread;
- apply explicit user-scoped preferences across different threads;
- pause a proposed action for human approval and resume after approval or
  rejection;
- turn verified findings into a validated Linear issue draft and create it
  only after approval (Human In The Loop);
- provide a conversational Streamlit interface with persistent threads,
  visible tool activity, and approval controls.

The project keeps changing facts in their authoritative systems. Conversation
history and long-term memory help interpret questions and apply preferences,
but current prices, sales figures, calculations, and Linear statuses are
retrieved again when needed.

## Current request flow

```text
Question
  -> load relevant user memory
  -> choose DuckDB, Linear, or both
  -> retrieve current evidence with filtered MCP tools
  -> analyze findings
  -> report, or draft an issue and pause for approval when action was requested
```

DuckDB access is read-only and model-generated SQL passes through a SQLGlot
allowlist. Linear analysis is read-only. A separate write adapter is available
only to guarded action nodes after a human approves the exact draft.

## Technology stack

- **Python 3.13** and **uv** for the runtime, dependencies, and lockfile.
- **Ollama** with `qwen3:4b-instruct` for local inference.
- **LangChain** for tool-using analysts.
- **LangGraph** for routing, state, checkpointing, memory, and interruption.
- **Model Context Protocol** for local DuckDB and remote Linear tools.
- **DuckDB** for fictional analytical data.
- **Linear MCP** for read-only context and separately authorized writes.
- **SQLGlot** for the SQL safety boundary.
- **SQLite** for thread checkpoints, long-term memory, and approval state.
- **Streamlit** for the local conversational interface.
- **pytest** for deterministic automated tests.
- **Ruff** for linting and formatting.

## Prerequisites

- Python 3.13 or newer
- [uv](https://docs.astral.sh/uv/)
- [Ollama](https://ollama.com/)
- Linear read credentials, plus separate write credentials when testing
  approved issue creation

## Setup

From the repository root:

```powershell
uv sync
ollama pull qwen3:4b-instruct
uv run python scripts/seed_database.py
```

Linear environment variables and exact development commands are documented in
[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md). Secrets, generated databases,
SQLite sidecars, and other local storage are excluded from version control.

The DuckDB dataset is a reproducible repository fixture generated by the seed
script. Linear records are not bundled: live Linear examples use issues and
teams from the configured workspace. The placeholder-only `.env.example` is
committed as setup documentation; copy it to the ignored `.env`, then add real
credentials and adjust fixture names for your workspace.

## Security scope

This is a local development prototype, not a production service. DuckDB is
opened read-only for analytical tools, generated SQL is restricted, and normal
Linear analysis uses the read-only endpoint. The separate write capability is
opt-in and reachable only after an explicit checkpointed approval.

Before deployment or enabling writes, add authenticated users, secure secret
storage, least-privilege credentials, authorization and audit records, request
limits and concurrency controls.
